## The Core Overview / Summary

While Lists and Tuples organize items by their position (0, 1, 2...), **Dictionaries** and **Sets** organize data using **keys** and **uniqueness**. Under the hood, both use a powerful mechanism called a **Hash Table**, making lookups and searches instantaneous ($O(1)$ time complexity).

| Data Structure | How It Stores Data | Duplicate Items? | Mutability | Real-Life Analogy |
| :--- | :--- | :--- | :--- | :--- |
| **Dictionary (`dict`)** | Key-Value pairs (`{key: value}`) | Keys must be unique; Values can repeat | Mutable | A phonebook (Contact Name $\rightarrow$ Phone Number) |
| **Set (`set`)** | Collection of unique items (`{1, 2}`) | **No duplicates allowed** (auto-removed) | Mutable | A classroom attendance sheet (each student listed once) |

## 1. Dictionaries: Key-Value Mappings

A **Dictionary** connects a unique identifier (a **Key**) to its data (a **Value**).

> [!NOTE]
> **Interview Definition:**  
> A **Dictionary** is an unordered (insertion-ordered in Python 3.7+), mutable collection of key-value pairs where keys must be unique and immutable.

### The Golden Rule of Keys
- **Keys** must be **immutable** (strings, numbers, or tuples). You cannot use a list as a key because lists can change!
- **Values** can be anything (numbers, lists, nested dictionaries, objects).

```python
# Student record dictionary
student = {
    "name": "Adarsh",
    "course": "AIML Prime 2.0",
    "score": 98,
    "skills": ["Python", "Machine Learning"]
}

print(student["name"])  # Output: Adarsh
```

## 2. Safe Lookups & Essential Dictionary Methods

### Safe Access: `dict.get()` vs `dict[key]`
If you look up a key that doesn't exist using square brackets `dict["missing"]`, Python crashes with a **`KeyError`**.  
Always use **`.get()`** for safe lookups—it returns `None` (or a fallback default value) instead of crashing:

```python
# Dangerous (crashes if key is absent):
# print(student["phone"])  <- KeyError!

# Safe (returns fallback value):
phone = student.get("phone", "Not Provided")
print(phone)  # Output: Not Provided
```

### Useful Dictionary Methods
```python
user = {"id": 101, "role": "admin", "active": True}

# 1. Update or add new keys
user.update({"role": "superadmin", "verified": True})

# 2. Removing an item
removed_role = user.pop("role")  # Removes 'role' and returns its value

# 3. Looping through both keys and values
for key, value in user.items():
    print(f"{key} -> {value}")
```

## 3. Sets: The Unique Collection

A **Set** is an unordered collection that automatically **removes all duplicate values**.

> [!NOTE]
> **Interview Definition:**  
> A **Set** is a mutable, unordered collection of distinct, unique elements.

```python
# Duplicates are automatically discarded!
numbers = [1, 2, 2, 3, 4, 4, 4, 5]
unique_numbers = set(numbers)

print(unique_numbers)  # Output: {1, 2, 3, 4, 5}
```

> [!IMPORTANT]
> **Creating an Empty Set Trap:**  
> Writing `{}` creates an **empty dictionary**, not an empty set! To create an empty set, you must write `empty_set = set()`.

## 4. Set Mathematical Operations

Sets let you perform math-style comparisons easily:

```python
batch_a = {"Python", "SQL", "Git"}
batch_b = {"Python", "Machine Learning", "Deep Learning"}

# 1. Union (|): Everything in either set
print(batch_a | batch_b)
# {'Python', 'SQL', 'Git', 'Machine Learning', 'Deep Learning'}

# 2. Intersection (&): Only items present in BOTH sets
print(batch_a & batch_b)
# {'Python'}

# 3. Difference (-): Items in A that are NOT in B
print(batch_a - batch_b)
# {'SQL', 'Git'}
```

### Adding & Removing Items in Sets
- **`.add(item)`**: Adds a single item.
- **`.remove(item)`**: Deletes an item, but crashes with `KeyError` if item isn't there.
- **`.discard(item)`**: Deletes an item safely without crashing even if it is missing.

## 5. Why Are Dictionaries and Sets So Fast? ($O(1)$ Lookups)

If you have a list of 1 million items and check `if "target" in my_list:`, Python has to scan through the list one by one ($O(N)$ linear time).

In contrast, checking `if "target" in my_set:` is almost **instantaneous** ($O(1)$ constant time).

### Why? The Hash Table Mechanism
Python converts each key into a number (a **hash**) that points directly to a specific slot in memory. Python jumps straight to that exact memory address instead of scanning from the beginning.

## Quick Interview Q&A (Cheatsheet)

### Q1: Can a list be used as a dictionary key?
> **Answer:**  
> No. Dictionary keys must be **hashable** (immutable), meaning their value cannot change over time. Lists are mutable and cannot be hashed, so using a list as a key raises a `TypeError: unhashable type: 'list'`.

### Q2: How do you safely look up a key in a dictionary without risking a `KeyError`?
> **Answer:**  
> Use the `.get(key, default)` method. If the key exists, it returns the value; if not, it returns `None` or your specified default value instead of crashing.

### Q3: What is the fastest way to remove all duplicates from a list?
> **Answer:**  
> Convert the list to a set using `list(set(my_list))`. Note that this does not preserve the original order of items.

### Q4: Why is checking `x in my_set` faster than checking `x in my_list`?
> **Answer:**  
> Lists take $O(N)$ time because Python has to scan through items one by one. Sets use a hash table under the hood, allowing lookups in average $O(1)$ constant time.
