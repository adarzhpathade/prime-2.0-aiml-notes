## The Core Overview / Summary

Inside a Python class, not all data and functions behave the same way. Some belong to **one specific object**, while others are shared across **the entire company or blueprint**. 

Understanding the distinction between **Instance, Class, and Static** members is a core requirement for writing clean Python and acing technical interviews.

| Concept | Who Owns It? | First Argument | Decorator | Real-Life Analogy |
| :--- | :--- | :--- | :--- | :--- |
| **Instance Attribute** | The specific object | N/A (Stored on `self`) | None | A student's personal roll number |
| **Class Attribute** | The entire class | N/A (Stored on class) | None | The school's name on everyone's uniform |
| **Instance Method** | The specific object | `self` | None | An employee doing their personal daily tasks |
| **Class Method** | The entire class | `cls` | `@classmethod` | HR announcing a company-wide holiday |
| **Static Method** | Isolated utility function | None (No `self`, no `cls`) | `@staticmethod` | A calculator sitting on an office desk |

## 1. Class Attributes vs. Instance Attributes

### The School Uniform Analogy
- **Class Attribute**: All students attend `"Delhi Public School"`. You don't need to write the school name 1,000 times in memory. It is shared by every student.
- **Instance Attribute**: Student A's roll number is 101, Student B's is 102. Each student has their own unique value.

> [!NOTE]
> **Interview Definition:**  
> - An **Instance Attribute** is a variable unique to each object instance, defined inside methods using `self`.  
> - A **Class Attribute** is a variable shared by all instances of a class, defined directly within the class body.

```python
class Student:
    # Class Attribute (Shared by all students)
    school_name = "Tech Academy"

    def __init__(self, name, roll_no):
        # Instance Attributes (Unique to this student)
        self.name = name
        self.roll_no = roll_no

s1 = Student("Adarsh", 1)
s2 = Student("Kavya", 2)

print(s1.name, s1.school_name)  # Adarsh Tech Academy
print(s2.name, s2.school_name)  # Kavya Tech Academy
```

> [!IMPORTANT]
> **The Shadowing Interview Trap:**  
> If you write `s1.school_name = "New School"`, you **do not** change the school for everyone! You only create a new private instance variable on `s1` that hides (shadows) the class variable. To change it for all students, you must change it on the class: `Student.school_name = "New School"`.

## 2. Instance Methods: Operating on a Specific Object

An **Instance Method** is the most common type of method. It takes `self` as its first parameter and can read or modify the object's personal data.

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    # Instance method: modifies this specific account's balance
    def deposit(self, amount):
        self.balance += amount
        print(f"Deposited ${amount}. New balance: ${self.balance}")

acc = BankAccount("Adarsh", 100)
acc.deposit(50)  # Deposited $50. New balance: $150
```

## 3. Class Methods: Operating on the Entire Class (`@classmethod`)

A **Class Method** does not care about an individual object's personal state. Instead of `self`, it takes **`cls`** (a reference to the class itself).

We mark it with the **`@classmethod`** decorator.

### Common Use Case: Alternative Constructor (Factory Method)
Imagine user data comes in as a formatted string like `"Adarsh-21"`. A class method can parse the string and build a `Student` object for you!

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    # Class method: acts as an alternative constructor
    @classmethod
    def from_string(cls, data_string):
        name, age = data_string.split("-")
        return cls(name, int(age))  # Calls Student(name, int(age))

# Normal creation:
s1 = Student("Adarsh", 21)

# Creation via Class Method:
s2 = Student.from_string("Priya-22")
print(s2.name, s2.age)  # Priya 22
```

## 4. Static Methods: Standalone Helper Functions (`@staticmethod`)

A **Static Method** is just a normal, independent function that doesn't need to know anything about `self` (the object) or `cls` (the class). It is placed inside the class simply because it is logically related to that topic.

We mark it with the **`@staticmethod`** decorator.

### The Office Calculator Analogy
A calculator on a desk doesn't care who the employee is or what company they work for. It just adds numbers when you push the buttons.

```python
class MathUtils:
    # Static method: pure utility helper, takes no self and no cls
    @staticmethod
    def is_even(number):
        return number % 2 == 0

# Call directly on the class without creating an object!
print(MathUtils.is_even(10))  # True
print(MathUtils.is_even(7))   # False
```

## Quick Interview Q&A (Cheatsheet)

### Q1: What is the difference between an instance method, a class method, and a static method?
> **Answer:**  
> - **Instance Method**: Receives `self`; accesses and modifies individual object state.  
> - **Class Method**: Marked with `@classmethod` and receives `cls`; accesses and modifies class-level state or builds objects.  
> - **Static Method**: Marked with `@staticmethod`; receives neither `self` nor `cls`; acts as an isolated utility helper function.

### Q2: What happens if you modify a class attribute through an instance (e.g., `obj.count = 5`)?
> **Answer:**  
> It creates a new instance attribute named `count` on that specific object that shadows the class attribute. The class attribute and other instances remain completely unchanged.

### Q3: When should you use a `@classmethod` instead of a regular method?
> **Answer:**  
> Use `@classmethod` when you need to access or modify class-level state (like tracking total users created) or when creating **alternative constructors** (factory methods) that build objects from raw data formats like JSON, strings, or files.

### Q4: When is a `@staticmethod` preferred?
> **Answer:**  
> When a function performs a self-contained calculation or validation related to the class domain, but does not read or change any object (`self`) or class (`cls`) variables.
