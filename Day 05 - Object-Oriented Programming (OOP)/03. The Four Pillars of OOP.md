## The Core Overview / Summary

The power of Object-Oriented Programming comes from its **Four Core Pillars**. These four concepts work together to make code safe, reusable, flexible, and easy to maintain.

| Pillar | What It Means (In Plain Words) | Primary Benefit | Real-Life Analogy |
| :--- | :--- | :--- | :--- |
| **1. Encapsulation** | Hiding internal data and restricting direct access | Prevents accidental data corruption | A medicine capsule or a bank ATM |
| **2. Inheritance** | Passing down features from a parent class to a child class | Eliminates duplicate code (reusability) | A child inheriting traits from parents |
| **3. Polymorphism** | The same action behaving differently based on the object | Maximum flexibility and clean APIs | The universal "Play" button on music/video apps |
| **4. Abstraction** | Showing only what is necessary and hiding the complex machinery | Simplifies using complex systems | Driving a car with pedals without knowing engine mechanics |

## 1. Encapsulation: Protecting Your Data

### The Medicine Capsule Analogy
When you take a medicine capsule, all the active chemicals are sealed inside a protective shell. You don't interact with the raw powder directly.
Similarly, **Encapsulation** bundles variables and methods together inside a class and prevents outside code from tampering with them directly.

> [!NOTE]
> **Interview Definition:**  
> **Encapsulation** is the bundling of data and the methods that operate on that data into a single unit (class), while restricting direct access to internal components using access modifiers.

### Access Levels in Python: Public, Protected, and Private
Python uses naming conventions for security:
1. **Public (`self.name`)**: Can be read and changed anywhere.
2. **Protected (`self._age`)**: Single underscore prefix. Serves as a polite warning: *"please don't touch outside this class or its children"*.
3. **Private (`self.__balance`)**: Double underscore prefix. Python restricts direct access via **Name Mangling**.

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner          # Public
        self.__balance = balance    # Private (Hidden!)

    # Getter: safe way to view balance
    def get_balance(self):
        return self.__balance

    # Setter: safe way to update balance with validation
    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
        else:
            print("Invalid deposit amount!")

acc = BankAccount("Adarsh", 500)

# Direct access to private attribute fails!
# print(acc.__balance)  <- AttributeError!

# Correct access through method:
print(acc.get_balance())  # 500
```

## 2. Inheritance: Reusing Existing Code

Instead of writing a new class from scratch, **Inheritance** allows a new class (Child / Subclass) to inherit all features from an existing class (Parent / Superclass).

> [!NOTE]
> **Interview Definition:**  
> **Inheritance** is a mechanism where a new class inherits attributes and methods from an existing parent class, enabling code reuse and hierarchical relationships.

```python
# Parent Class
class Animal:
    def eat(self):
        print("This animal eats food.")

# Child Class inherits Animal
class Dog(Animal):
    def bark(self):
        print("Woof! Woof!")

d = Dog()
d.eat()   # Inherited from Animal: This animal eats food.
d.bark()  # Defined in Dog: Woof! Woof!
```

### The `super()` Function
The **`super()`** function allows a child class to call the parent class's constructor or methods without typing the parent's name manually:

```python
class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, student_id):
        super().__init__(name)  # Calls Person.__init__
        self.student_id = student_id
```

### The 5 Types of Inheritance in Python
1. **Single Inheritance**: Child inherits from 1 Parent (`A -> B`).
2. **Multiple Inheritance**: Child inherits from multiple Parents (`A, B -> C`).
3. **Multilevel Inheritance**: Grandparent $\rightarrow$ Parent $\rightarrow$ Child (`A -> B -> C`).
4. **Hierarchical Inheritance**: Multiple children inherit from 1 Parent (`A -> B` and `A -> C`).
5. **Hybrid Inheritance**: A mix of two or more types.

## 3. Polymorphism: One Name, Many Forms

"Poly" means **many**, and "Morph" means **forms**. 

### The Universal "Play" Button Analogy
On your smartphone, clicking the **Play button** plays a song on Spotify, a video on YouTube, or an audio track on a podcast app. The button action is the same (`play()`), but the behavior changes based on what you are playing.

### 1. Method Overriding
A child class provides its own specific implementation of a method that is already defined in its parent class:

```python
class Shape:
    def area(self):
        print("Calculating area...")

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side * self.side

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    def area(self):
        return 3.14 * (self.radius ** 2)

shapes = [Square(4), Circle(3)]
for s in shapes:
    print("Area:", s.area())  # Runs the respective method automatically!
```

### 2. Duck Typing in Python
Python follows a famous philosophy:  
> *"If it walks like a duck and quacks like a duck, it's a duck!"*

Python does not care what type of class an object belongs to. As long as the object has the required method (e.g., `.fly()`), Python runs it without complaining:

```python
class Airplane:
    def fly(self):
        print("Flying with jet engines")

class Bird:
    def fly(self):
        print("Flying with wings")

# This function doesn't care if 'entity' is a Bird or Plane!
def lift_off(entity):
    entity.fly()

lift_off(Airplane())  # Flying with jet engines
lift_off(Bird())      # Flying with wings
```

## 4. Abstraction: Hiding Complex Machinery

### The Car Pedals Analogy
When you press the accelerator pedal in a car, the car speeds up. You do not need to understand engine fuel ratios, valve timings, or combustion chamber physics. The complex engineering is **abstracted away**, giving you a simple pedal.

In Python, we use the **`abc`** (Abstract Base Classes) module to create blueprints that **force** child classes to implement required methods.

> [!NOTE]
> **Interview Definition:**  
> **Abstraction** is the process of hiding internal implementation details and exposing only essential interfaces. In Python, it is enforced using Abstract Base Classes (`ABC`) and the `@abstractmethod` decorator.

```python
from abc import ABC, abstractmethod

# Abstract Class (Cannot be instantiated directly!)
class PaymentGateway(ABC):
    @abstractmethod
    def pay(self, amount):
        pass  # Forces subclasses to implement this method

class UPI(PaymentGateway):
    def pay(self, amount):
        print(f"Paid ${amount} using UPI QR code")

class CreditCard(PaymentGateway):
    def pay(self, amount):
        print(f"Paid ${amount} using Credit Card OTP")

# gateway = PaymentGateway()  <- Error! Cannot instantiate abstract class!
upi = UPI()
upi.pay(50)  # Paid $50 using UPI QR code
```

## Quick Interview Q&A (Cheatsheet)

### Q1: What are the Four Pillars of OOP?
> **Answer:**  
> 1. **Encapsulation**: Bundling data and restricting direct outside access.  
> 2. **Inheritance**: Reusing code by allowing a child class to inherit from a parent class.  
> 3. **Polymorphism**: Allowing different classes to share the same method interface with different behaviors.  
> 4. **Abstraction**: Hiding internal implementation details and exposing only the essential interface.

### Q2: How does Python achieve private variables if it lacks a `private` keyword?
> **Answer:**  
> Python prefixes variables with a double underscore (e.g., `__balance`). Python performs **Name Mangling**, internally renaming the variable to `_ClassName__variable` so it cannot be accessed directly by its original name from outside.

### Q3: What is "Duck Typing"?
> **Answer:**  
> Duck Typing is Python's dynamic typing approach where an object's suitability is determined by the presence of specific methods and properties, rather than its explicit class type inheritance.

### Q4: What happens if a subclass does not implement an `@abstractmethod`?
> **Answer:**  
> Python raises a `TypeError` and prevents the subclass from being instantiated, guaranteeing that all required interface methods are provided.

### Q5: What is Method Resolution Order (MRO)?
> **Answer:**  
> In multiple inheritance, MRO is the exact order in which Python searches for attributes and methods across parent classes. You can check it via `ClassName.mro()` or `ClassName.__mro__`.
