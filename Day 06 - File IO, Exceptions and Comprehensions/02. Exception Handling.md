## The Core Overview / Summary

No matter how carefully you write code, unexpected things happen at runtime: a user enters letters instead of a number, a requested file is missing from the disk, or an internet connection drops.

Without **Exception Handling**, any error immediately crashes your program with a red error screen. With exception handling, your code catches the problem gracefully, shows a helpful message, and keeps running smoothly.

| Keyword | What It Does (In Simple Words) | When It Runs | Real-Life Analogy |
| :--- | :--- | :--- | :--- |
| **`try`** | Tests a block of code for errors | Always runs first | An acrobat attempting a risky jump |
| **`except`** | Handles the error if one occurs | Runs **only if** an error happened in `try` | The safety net catching the acrobat |
| **`else`** | Extra code to run on complete success | Runs **only if** no errors happened | The audience cheering for a successful jump |
| **`finally`** | Guaranteed cleanup code | **Always runs**, error or no error | Turning off the gas stove before leaving |
| **`raise`** | Intentionally triggers an error | When business rules are violated | A referee blowing a whistle for a foul |

## 1. Syntax Errors vs. Runtime Exceptions

- **Syntax Error (Parsing Error)**: A typo in your code that Python catches before running (e.g., forgetting a colon `:` or misspelling `def`).
- **Runtime Exception**: Code syntax is valid, but an error occurs while running (e.g., dividing by zero or opening a file that was deleted).

> [!NOTE]
> **Interview Definition:**  
> An **Exception** is an event detected during program execution that disrupts the normal flow of instructions. Exception handling allows a program to intercept and resolve these events without terminating abruptly.

## 2. The 4-Part Structure: `try`, `except`, `else`, `finally`

```python
try:
    number = int(input("Enter an integer: "))
    result = 100 / number

except ZeroDivisionError:
    # Catches division by zero
    print("Error: You cannot divide by zero!")

except ValueError:
    # Catches invalid conversions (e.g., typing 'hello')
    print("Error: Please enter a valid number, not text!")

else:
    # Runs ONLY if the try block succeeded without errors
    print(f"Success! The result is {result}")

finally:
    # Runs NO MATTER WHAT (Even if an error occurred!)
    print("Execution complete. Cleaning up resources.")
```

## 3. The `finally` Keyword: Guaranteed Resource Cleanup

### The Kitchen Stove Analogy
Imagine you are cooking dinner:
- You turn on the gas stove.
- If the food cooks well $\rightarrow$ you turn off the stove.
- If the recipe catches fire and burns $\rightarrow$ you **still MUST turn off the stove** before dealing with the mess.

In programming, **`finally`** is used for tasks that must never be skipped:
- Closing database connections.
- Disconnecting network sockets.
- Closing open file handles.

> [!IMPORTANT]
> **Interview Favorite:**  
> The `finally` block runs even if your `try` or `except` block contains a `return` statement! Python will execute the `finally` code first before finally returning.

## 4. Catching Specific Exceptions vs. The "Bare Except" Anti-Pattern

### The Anti-Pattern: Catching Everything Blindly
```python
# Bad practice (Silent failure):
try:
    process_data()
except:
    pass  # Swallows every single error, making bugs impossible to find!
```

### The Best Practice: Catch Specific Errors
Always name the exact exceptions you expect to encounter:
- `FileNotFoundError`: Missing file.
- `ValueError`: Incompatible data types (e.g., `int("abc")`).
- `KeyError`: Looking up a non-existent dictionary key.
- `IndexError`: Accessing a list index that is out of bounds.

```python
# Clean and specific:
try:
    user_id = data["id"]
except KeyError:
    print("User ID key is missing from payload.")
```

## 5. Raising Exceptions Manually (`raise`)

Sometimes data is technically valid in Python, but invalid for your program's rules (e.g., a person's age cannot be negative `-5`). You can trigger an exception intentionally using **`raise`**:

```python
def register_voter(age):
    if age < 0:
        raise ValueError("Age cannot be a negative number!")
    if age < 18:
        print("Not eligible to vote.")
    else:
        print("Registration successful.")

register_voter(21)
# register_voter(-5)  <- Raises ValueError: Age cannot be a negative number!
```

## Quick Interview Q&A (Cheatsheet)

### Q1: When does the `else` block execute in a `try-except` statement?
> **Answer:**  
> The `else` block executes only if the code inside the `try` block ran to completion without raising any exceptions.

### Q2: What is the primary purpose of the `finally` block?
> **Answer:**  
> It guarantees execution of cleanup code (like closing files, freeing locks, or closing database connections), regardless of whether an exception occurred, was handled, or even if a `return` statement was encountered.

### Q3: Why is a "bare except" (`except:`) considered bad programming practice?
> **Answer:**  
> A bare `except:` catches every possible exception, including system exits (`SystemExit`) and keyboard interrupts (`KeyboardInterrupt` / Ctrl+C). This masks critical programming bugs and prevents graceful script termination.

### Q4: What is the difference between an Error and an Exception?
> **Answer:**  
> Errors are typically severe issues often related to environment or memory (like `SyntaxError` or `MemoryError`) that a program usually cannot recover from. Exceptions are conditions caused by application logic (like `ZeroDivisionError` or `FileNotFoundError`) that can be anticipated and handled gracefully.
